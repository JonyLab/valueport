# 估值情景选择与分步引导

新估值在引导入口选择单场景或保守／乐观两种方式。

- 单场景使用中性的主情景：经营问答 → 叙事确认 → 方法 → 参数 → 合理价值确认。
- 双场景先完整完成保守情景，再完整完成乐观情景，最后并排比较。两边沿用同一个估值方法与基础数据；乐观情景只修改自身假设。
- 两边的回答、草稿、参数确认与进度独立保存。修改共同基础或已确认参数会撤销受影响的参数确认，保留问答与叙事。
- 已有回答的旧版引导保留原流程，未开始的草稿显示新选择入口。

`scenarioContext` 在客户端与 AI 服务端筛掉另一情景和已有目标区间；`mergeScenarioParams` 只采用当前情景的参数。独立结果使用 `runScenario`，不依赖另一边参数是否完整，也不交换保守和乐观的身份。

单场景卡片带 `scenarioMode: "single"`，使用相等的正数 `low`、`high` 存储一个估值点。只有明确标记且被选中的单场景卡片，才能使相等的 `fairLow`、`fairHigh` 生效。旧卡片和区间卡片继续要求 `high > low`。钟摆支持单点合理价值。

验证：`test-core/scenario-flow.test.js`、`test/ai.test.js`、`test/items.test.js` 覆盖进度恢复、情景隔离、部分参数更新、单点保存与判定。`test-helpers/scenario-flow.html` 是本地浏览器模拟夹具，只返回虚构回复，并拒绝未声明的网络调用；勿发布为产品入口。

## AI 复核

复核请求显式携带 `scenarioMode`，单场景字段按主情景标量传入，服务端再次裁剪另一情景。新版复核带 `version: 2`、`scenarioMode`、`valuedAt` 和逐项证据快照，保存后仍可还原当时的比较依据。版本、场景或估值日期不匹配的旧结果折叠为过期记录，不计为新的 AI 复核。

`review.js` 统一两位小数的展示和比较，注明年度、历史 CAGR 区间与来源。历史 CAGR 必须有相隔三年的端点；利润率分子分母必须属于同一财年。历史增速和利润率仅为预测参照，倍数对照不能独立证明目标合理；缺资料不自动判定失效。接口数据没有提供原文页码时如实提示。

复核 UI 按原假设、可比数据、数值对照、判断、验证条件排列；趋势图放在文字下方并标注年度范围。过期记录保留原文，重新复核仍由用户发起。`test-helpers/review-preview.html` 使用虚构数据验证排版，不调用模型。
