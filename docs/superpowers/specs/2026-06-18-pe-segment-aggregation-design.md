# PE 分部加总(Segment-Aggregated Earnings)— 设计

日期:2026-06-18
状态:已通过 brainstorm,待实现计划

## 背景与目标

多业务公司各分部的增速、利润率不同,混成一个数会失真。本特性给 **PE 估值模型**加一个可选的「分部加总」表:逐个业务填当前营收、增速、净利率,自下而上算出第 n 年的合计净利(E),再走 PE 估值。灵感来自卖方研报/参考工具的"据年报分部、按收入加权"。

PE 只用第 n 年的 `E × 目标PE`,因此分部加总到 E 与"混合增速+混合净利率回填"完全等价——**精确无损**。FCFF 等需逐年贴现的模型暂不做(留作以后)。

## 关键决策(brainstorm 结论)

- **仅 PE 模型**。
- 每个分部填 `当前营收`(单值)+ `营收增速{保守,乐观}` + `净利率{保守,乐观}`;合计营收 = 各部之和。
- 分部区**驱动 PE 的三个字段**:`当前营收`、`营收增速`、`净利率`;`预测年数 n` 仍单一手填、各分部共用;`目标 PE` 不受影响。
- 架构 A:**顶部独立「分部」区 + 开关**,与已有的单字段 ▾ 推导 并列、互不打架(开启分部时隐藏营收增速的 ▾ 推导)。
- 分部的增速/利润率各分保守|乐观;但**不做**每个分部内再拆 行业+份额+提价(留作以后)。

## 分部表 + 计算

**每个分部一行**:`业务名`(文本) · `当前营收`(金额单值) · `营收增速{保守,乐观}`(%) · `净利率{保守,乐观}`(%)。`占比%` = 当前营收 ÷ 合计营收,自动算出、只读。可加行 / 删行。

顶部汇总行(以"合计净利 E"为主,贴合用户心智:ΣEᵢ × PE = 估值):
- `合计当前营收` R0
- `合计第 n 年净利 E` 保守 / 乐观(= 各分部未来净利之和,FEₛ)
- 次要:`隐含混合增速` 保守/乐观(供参考,呼应"自下而上整体增速")

**计算**(保守、乐观各算一次,记情景 s ∈ {c, o}):
- 合计当前营收 `R0 = Σ revenueᵢ`
- 分部第 n 年营收 `FRᵢ,ₛ = revenueᵢ × (1 + growthᵢ,ₛ/100)ⁿ`;合计 `FRₛ = Σ FRᵢ,ₛ`
- 合计第 n 年净利 `FEₛ = Σ (FRᵢ,ₛ × marginᵢ,ₛ/100)`
- 写回 PE 三字段:
  - `revenue = R0`
  - `growthₛ = ((FRₛ / R0)^(1/n) − 1) × 100`
  - `netMarginₛ = FEₛ / FRₛ × 100`
- PE 据此重算:`futRev = R0 × (1+growthₛ/100)ⁿ = FRₛ`,`futNi = FRₛ × netMarginₛ/100 = FEₛ` → E 精确等于分部加总。
- 最终估值 = `FEₛ × 目标PEₛ`(保守用 FE 保守 × PE 保守,乐观同理),即"各分部净利相加 × 总 PE"。回填混合增速/净利率纯属复用现有 PE 模型的内部手法,数学上与直接 ΣEᵢ × PE 恒等。

`n` 取 PE 模型的"预测年数"字段值。`n` 为空、或分部不足 1 行、或 `R0 ≤ 0` 时不写回、给提示,模型回退到字段上的手填值。

纯计算抽到新模块 `public/shared/valuation/segments.js`:
```js
// rows: [{ revenue:Number, growth:{c,o}, netMargin:{c,o} }]
// 返回 { revenue, growth:{c,o}, netMargin:{c,o} } 或 null(输入不足)
export function aggregateSegments(rows, n) { ... }
```
(`name`/`占比` 是 UI 层的事,聚合函数只吃数值。)

## 数据结构与存储

卡片新增 `segments`,与 `inputs` / `derivations` 并存:
```js
card.segments = {
  enabled: Boolean,
  rows: [{ name: String, revenue: Number, growth: { c, o }, netMargin: { c, o } }]
}
```
- `inputs.revenue/growth/netMargin` 始终保存分部算出的值(runModel 不变)。
- 服务端 `src/items.js` 的 `validateValuations` 放行 `segments`:是对象即存(轻校验,与 `inputs`/`derivations` 同等宽松);非对象 → `{}`(视为未启用)。
- 重开 PE 卡片:若 `segments.enabled` 且 `rows` 非空 → 重建分部表、重算、写回三字段。

## 交互(架构 A)

- PE 模型的表单顶部(方法下拉之下、前提卡之上)显示「分部」区,头部一个 **「分部加总」开关**。
- **关**(默认):现状——营收/增速/净利率手填,营收增速可用单字段 ▾ 推导。
- **开**:显示分部表;`当前营收`/`营收增速`/`净利率` 三字段变**只读 + "由分部得出"**;隐藏营收增速字段的单字段 ▾ 推导(避免双重来源);`目标 PE`、`预测年数 n` 照常手填。
- 分部表内任一格变更 → 重算 → 写回三字段 → 右侧结果卡刷新。
- 仅 PE 模型显示分部区;切到其它方法不显示(其 `segments` 数据保留但不生效)。

## 本批不做(YAGNI)

- 仅 PE。FCFF / PS / EV-EBITDA / DCF / FCFE / DDM 不挂分部。
- 不做分部级折现 / 各自估值(非完整 SOTP)。
- 不做每个分部内再拆「行业 + 份额 + 提价」(分部增速直接填 {保守,乐观})。
- 不从年报自动拉分部数据(手填;以后可接长桥分部披露)。

## 测试

`test-core/` 新增 `valuation-segments.test.js`:
- 两个分部、不同增速/利润率 → 混合增速 + 混合净利率,且用回填值重算的 `futNi` 等于分部 `Σ FEᵢ`(精确性断言)。
- `n` 缺失 / 0 行 / `R0 ≤ 0` → 返回 `null`。
- 保守、乐观两套各自正确。
